# Deploy Property Buy Route Without Disturbing Existing Routes

## Summary

GitHub Pages publishes one complete artifact from `projects/zyne-homepage/dist`; it cannot independently publish only the new folder. Integrate the `zyne-buy` production build into that artifact at:

`/homedetail/7101-wendemere-st-houston-tx-77088/buy/`

The existing property page, services, legal pages, homepage, and all other subdirectories remain generated by their current pipeline.

## Implementation Changes

* Build `projects/zyne-buy` first using its existing validation, tests, and Vite build.
* Add a narrowly scoped integration script to the homepage build:

  * Copy only the generated `buy/` route into the existing property directory.
  * Merge only the buy page’s required `/assets/` files.
  * Never replace the parent property page or unrelated directories.
  * Reject conflicting asset paths unless the files are byte-identical.
  * Fail if the expected buy entry point or referenced assets are missing.
* Run integration after the existing parent property generator and before SEO and route validation.
* Add the buy route to generated-route and sitemap validation.
* Update the root build command to build both applications in the required order.
* Update the GitHub Pages workflow to:

  * Install dependencies from the existing root and buy lockfiles.
  * Build `zyne-buy`.
  * Build the homepage and merge the route.
  * Trigger when either application, integration script, lockfile, or deployment workflow changes.
  * Upload the same single homepage artifact currently used by GitHub Pages.
* Update both project READMEs to document the combined deployment process. Do not commit generated `dist`, caches, or dependencies.

## Validation and Deployment

* Before editing, clean generated artifacts and record `git status --short`.
* Dry-run the integration against expected route and asset locations; stop unless each expected source matches exactly once.
* Run fresh installs and builds for both projects.

  * No existing artifact file is overwritten with different content.
  * Sitemap contains both the parent property route and `/buy/`.
* Serve the combined homepage artifact locally and perform browser checks at 1920×1080 and 1366×768.
* Test direct navigation, refresh, gallery/lightbox controls, scrolling, fonts, images, and browser console/network errors.
* Commit this as one isolated deployment-integration patch and push to the existing `origin/main`.

  * The new URL returns HTTP 200 with expected page markers.
